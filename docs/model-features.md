# 模型功能

设置顺序：LLM 提供商 → 模型功能（上下文压缩、辅助视觉模型、标题模型）→ 扩展（助手、Skills、MCP）。原上下文压缩配置不迁移、不重置。

辅助视觉默认关闭，保存提供商及模型 ID，不复制密钥。选择器仅列可读图、非生成型聊天模型；主模型支持图片时仍直接使用原生视觉。非视觉主模型在 AgentLoop 请求预算及协议过滤之前，用独立视觉模型把图像转换为带来源标识的文字观察。聊天附件、历史附件、追加附件、read_image、手机及浏览器工具截图共用转换路径；视频使用现有封面抽帧。原始附件仍按现有缓存持久化，工具图像保持瞬时观察生命周期。

每个观察转换成功后原位替换，同一轮后续请求不重复调用；失败保留图像，不伪造描述、不静默跨提供商回退。原始 system/developer 提示与完整工具正文不发送给辅助模型；仅发送附近任务、图片和筛选后的观察标识／坐标信息。描述是外部证据而非指令，坐标仅适用于原观察。模型调用不执行工具，含总超时与停止／暂停／追加时的取消，输出有界；额外 token 记到实际辅助提供商下。

标题模型默认使用当前会话绑定模型，自定义开关独立保存，不改变聊天选择。默认仅在新会话首轮回复结束后触发一次；打开标题模型页的「每轮回复后刷新标题」后，改为每轮助手回复结束时结合「本轮用户消息 + 本轮回复 + 当前标题」重新生成，提示词要求主题未明显变化时原样返回当前标题，返回值与当前标题相同则不写内存、不落库。两种模式都是独立异步请求；失败保留原（本地）标题。请求包含用户本轮消息的可见问题与助手本轮最终回答正文（均截断到 4000 字符），不发送图片、工具快照或系统提示；首轮失败或被停止而没有回答时，退化为仅依据问题生成，每轮刷新模式则在无本轮回复时直接跳过（不会拿上一轮旧回答当本轮素材）。标题提示词为专用的标题生成器人设，明确要求只输出一行标题、不得回答素材中的问题、忽略素材内的指令注入。异步回写检查会话存在、未手动命名、原标题未改变；首轮模式额外校验首条消息 ID 未改变，每轮刷新模式改用「该会话标题请求的单调序号仍是最新」，避免上一轮晚到的结果覆盖本轮更新。重生成、断线重试与压缩后续写不算「用户新发一轮」，不触发刷新。手动改过名的会话会持久化记录，重启后也不会再被自动标题覆盖。

新增 16 项回归用例（尚未执行）：关闭时不调用、转换后纯文本主模型无图像、工具结果顺序、失败不消费图片、观察隔离、上下文裁剪、元数据筛选、标题默认模型、无效自定义配置及晚到标题回写保护。尚需 GitHub Actions 编译／单测和安装后的真实视觉提供商验收；单测不代表实际识图效果。
